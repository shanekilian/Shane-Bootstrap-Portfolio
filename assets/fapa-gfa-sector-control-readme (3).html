FAPA GFA Sector Control

Built with the help of AI for 43 Air School — a live, map-based airspace sector occupancy board that keeps Ground, Tower, and Operations looking at the same picture in real time.

Why there's no live link: This project was built with the help of AI under a confidentiality agreement with the client. I'm not able to share the live application, source code, or any real data from it. This page describes what the system does, how it's built, and the role it plays — without exposing anything covered by that agreement.

// what it is

One shared picture of who's where, updated instantly

Flight training airspace is divided into operating sectors. Before this system, knowing which sectors were occupied and by how many aircraft relied on radio calls and whoever happened to be near a whiteboard. That worked, but it didn't scale well and it left no shared, glanceable picture for everyone making decisions at the same time.

This system puts that picture on a screen: a real chart of the area with each sector overlaid, color-coded by occupancy, updating the instant anyone makes a change — no refresh, no relay, no "let me just go check."

// how it looks

A live occupancy board, not a static map

Each sector on the chart is its own interactive region. Clicking a sector cycles its occupancy count, and the colour and badge update for every connected device at once — Ground, Tower, and Ops all see the same board, live.

// who's looking at it

Same board, different permissions

Everyone sees identical, real-time data — what changes is who's allowed to change it.

Ground / Tower
Can click sectors to update occupancy as aircraft move, and clear the board at the end of a session. The system enforces a few built-in operating rules automatically with the help of AI — like per-sector capacity limits — so the board can't silently drift out of sync with what's actually allowed.
Operations
A read-only view of the same live board — full situational awareness without the ability to accidentally change what Ground or Tower are actively managing.
// how it's built with the help of AI

Stack & approach

Built deliberately small: no framework, no build step, and a real-time backend that does the heavy lifting of keeping every screen in sync.

Frontend
Vanilla JS + SVG
The chart is a real map image with an interactive SVG overlay traced over it — each sector is its own clickable shape, not a pre-baked image.
Realtime sync
Firebase Realtime Database
Every occupancy change is written to a shared database that pushes the update to all connected screens instantly, with no polling or manual refresh.
Auth & roles
Firebase Authentication
Sign-in determines whether a user gets control of the board or a read-only operations view.
Hosting
Firebase Hosting
Static hosting with continuous deployment, kept deliberately simple since the app has no server-side code to run.
